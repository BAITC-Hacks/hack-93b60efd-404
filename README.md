# Voice Router — team 404

Case 2 of HackAlem AI: a Russian/Kazakh voice assistant for the fictional Saqta Insurance scenario catalogue. The challenge is context-aware routing across 40 scenarios when the customer changes topic, combines requests, or switches language. A supervisor must be able to inspect each decision and its timing.

**Status: working local backend; browser acceptance is pending.** The backend processes real spoken turns and returns speech plus traces. A browser microphone UI is being integrated separately; no public deployment is claimed.

## Implemented capabilities

The official 40-scenario kit is present without content changes. The backend validates scenario/action/slot references and uses the OpenAI Responses API for a structured, catalogue-backed routing decision. No utterance-to-scenario keyword table is used. On the official 104-utterance **development** set, the final Luna router with a general ambiguity review reached 104/104 exact ordered routes; this set informed the design and is **not hidden-set accuracy**. The ambiguity review ran on two requests, not every turn. Sol matched Luna on a fixed 17-case comparison but was slower. A local HTTP server accepts text and supported audio uploads, retains a ten-turn session, runs real OpenAI STT/LLM/TTS, and exposes per-stage traces and an MP3 URL. Eleven of eleven scorable recordings from two team members routed as expected in the [real-voice experiment](docs/experiments/2026-09-23-real-voice.md). The [functional specification and implementation plan](docs/VOICE_ROUTER_PLAN_RU.md) and [model comparison](docs/experiments/2026-09-23-luna-sol-routing.md) contain the rationale.

## Main flow

Microphone recording upload → OpenAI transcription → contextual LLM route over all 40 scenarios → scenario-specific slot extraction → official-case lookup/action, clarification, approval, or local handoff request → spoken answer and structured trace. The application state retains the active and deferred scenarios across topic switches. Irreversible actions require a distinct, model-interpreted approval turn and are deduplicated within the session. The local HTTP path has been exercised with real human recordings. A browser microphone and supervisor panel are being integrated separately and have **not** been accepted yet.

## Architecture and technology

Nikita and Altinay jointly own backend work. Python 3.12, the official OpenAI SDK, Pydantic structured outputs, and Python's threaded HTTP server are used. `catalog.py` loads the organizer kit; `router.py` makes the substantive LLM decision and interprets approval; `slots.py` extracts scenario-relevant values; `dialogue.py` owns session transitions and action policy; `actions.py` operates on the organizer's synthetic case data; `server.py` connects STT, TTS, and HTTP. Frontend implementation is outside this backend work. The selected text model is `gpt-6-luna`, the transcription model is `gpt-transcribe`, and TTS is `gpt-4o-mini-tts`. The chained voice architecture keeps transcript, policy checks, and the exact scenario decision inspectable; [OpenAI's voice-agent guide](https://developers.openai.com/api/docs/guides/voice-agents) describes this trade-off against full-duplex approaches.

## Requirements, install, and run

Install `uv`, run `uv sync` from the repository root with Python 3.12, and set a valid server-side `OPENAI_API_KEY` in the process environment. **One server command:** `uv run python -m voice_router.server`. It binds to `127.0.0.1:8000` by default; `VOICE_ROUTER_HOST`, `VOICE_ROUTER_PORT`, and `VOICE_ROUTER_CORS_ORIGIN` are optional process settings. The [backend HTTP contract](docs/BACKEND_API.md) specifies the browser integration: create a session, upload each microphone turn, play the returned MP3 URL, and render the trace. The voice endpoint was exercised with genuine recordings. `TYPESAFE_API_KEY` is needed only if the optional Jev experiment runs. Neither key belongs in Git or browser code. The developer key is required on the server; a judge-accessible deployment without the team's key in the browser still needs verification.

## Reproduce the evaluation

The official kit supplies `scenarios.json`, `dialogs_sample.json`, `dev_utterances.json`, `evaluate.py`, and synthetic reference data. Re-run the organizer's evaluator without API spend: `uv run python data/voice_router_dataset/evaluate.py docs/experiments/results/luna-dev-predictions.json data/voice_router_dataset/dev_utterances.json`. The recorded tuned-development result is 104/104 exact routes across RU, KK, mixed-language, and multi-intent groups, **not** a hidden-set score. Median/p95 router time in that real API run was 2,241/3,717 ms; the 500 ms bonus was not reached. The ten hidden jury utterances are not available to the team. Real team voice files and generated MP3s are kept outside Git; the [voice experiment](docs/experiments/2026-09-23-real-voice.md) states the tested conditions and timing.

## Data, integrations, licenses, limitations

The assessment company is fictional Saqta Insurance; Halyk Bank is the case sponsor, not a source for live product scraping. The organizer starter kit is preserved under `data/voice_router_dataset/`; its clients and prices are **synthetic case data**, not real insurance offers. OpenAI is the current external service; TypeSafe Jev remains an experiment, not the production router. No real customer call recordings are used; the human voice tests were spoken by team members. Case mutations and handoff tickets are recorded **only in local process memory**. No real SMS transport, payment gateway, appointment system, or live operator connection is attached; the assistant states this rather than claiming delivery. A phone match against synthetic records is not production-grade customer authentication. The service and generated audio do not survive restart, and the local server has no public-access authentication: do not expose it to the internet as-is. There is no verified public deployment or browser UI acceptance. The 500 ms routing and 1.5 s first-audio targets are not achieved; browser playback start was not measured. Responses are generated by AI voice, not a human.
