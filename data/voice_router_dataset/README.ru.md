# Voice Router — датасет

Датасет для кейса 2: голосовой ИИ-агент контакт-центра страховой компании **Saqta Insurance**. Агент выбирает подходящий сценарий с помощью LLM-слоя (без классификатора намерений) и общается как квалифицированный оператор — на казахском и русском языках.

Все данные синтетические. Компания Saqta Insurance, её продукты, цены, правила, клиенты, адреса и клиники вымышлены и упрощены. Они не отражают реальное законодательство.

**Дата среза данных:** `2026-10-01`. Считайте эту дату «сегодняшней».

## Компания

**Saqta Insurance** — компания общего страхования (не страхование жизни) в Казахстане. Основана в 2009 году, головной офис находится в Алматы. У компании 8 филиалов и около 600 000 клиентов. Обслуживает физических и юридических лиц на казахском и русском языках.

| Направление | Продукты |
|---|---|
| Автострахование | ОГПО (обязательное страхование гражданско-правовой ответственности владельцев транспортных средств), КАСКО (добровольное страхование автомобиля) |
| Медицинское страхование | ДМС (добровольное медицинское страхование): преимущественно корпоративное, также индивидуальное |
| Страхование путешествий | Медицинская страховка для поездок за границу, круглосуточная медицинская помощь |
| Страхование имущества | Квартиры и дома |
| Страхование от несчастных случаев | Страхование физических лиц от несчастных случаев |

Не предоставляются: страхование жизни, пенсионные аннуитеты и кредиты. Такие запросы относятся к `SYS_OUT_OF_SCOPE`.

Режим работы контакт-центра: продажи — пн–сб, 08:00–20:00; урегулирование страховых случаев и медицинская помощь — круглосуточно.

**Почему страховые звонки сложно обрабатывать**

- Одни и те же слова могут относиться к разным сценариям: «авария» может означать **ДТП, которое произошло только что** (SC11), **обращение пострадавшего** (SC12) или **страховой случай по КАСКО** (SC13).
- Запрос статуса и несогласие с решением — разные случаи: «выплату одобрили, но сумма слишком маленькая» — это несогласие (SC19), а не запрос статуса (SC17).
- Неотложные случаи — ДТП на дороге, заболевание за границей, мошенничество — необходимо распознавать и обрабатывать в первую очередь.
- Клиенты могут менять тему и язык прямо в середине фразы.
- Многие действия необратимы — оформление, изменение или расторжение полиса, регистрация страхового случая — и требуют явного подтверждения.

### slots.json

`name`, `type` (`string`, `enum`, `integer`, `date`, `boolean`, `list`, `text`), `description`, `pattern` или `values`, `prompt.ru`, `prompt.kk`.

Нормализуйте значения, произнесённые клиентом: «восемь семьсот один…» → `+7701…`, «ертең» → дата, «двадцатого года» → `2020`. Даты определяются относительно даты среза данных.

### actions.json

`name`, `description`, `inputs`, `outputs`, `errors`, `irreversible`. Реализуйте их как моки поверх `mock_backend.json` и `knowledge_base.json`. В `queues` перечислены направления перевода на оператора.

Ошибки используют единый формат: `{"error": {"code": "not_found", "message": "..."}}`. Коды перечислены в `error_codes`, а ожидаемое поведение агента — в `error_handling`. Пример: неизвестный номер телефона → `find_client` возвращает `not_found` → агент повторно запрашивает номер один раз, затем предлагает использовать другой идентификатор или соединить с оператором.

Необратимые действия: `create_policy`, `renew_policy`, `update_policy`, `cancel_policy`, `create_claim`, `create_dispute`, `book_inspection`, `book_appointment`, `update_contact`.

### knowledge_base.json

Сведения о компании, офисах, пунктах осмотра, продуктах и формулах расчёта стоимости, клиниках, правилах урегулирования и списках документов, платежах, расторжении полисов, системе бонус-малус, мобильном приложении, противодействии мошенничеству и жалобах. Агент должен отвечать только на основании этого файла и не придумывать факты.

Каждый диалог содержит: `dialog_id`, `title`, `tags`, `client_id`, `turns`. Реплики клиента: `text`, `lang`, `scenarios` (ожидаемые сценарии по порядку), `slots` (слоты, извлечённые из текущей реплики). Набор охватывает: смену сценария; смену темы с последующим возвратом; смешанную речь; смену языка; уточнение; перевод на оператора; необратимое действие с подтверждением.

### dev_utterances.json

`id`, `text`, `lang` (`ru`, `kk`, `mixed`), `expected` (упорядоченный список ID сценариев), `type` (`single`, `multi_intent`, `out_of_scope`, `unclear`). Состав набора: 84 одиночных запроса, 13 запросов с несколькими намерениями, 4 запроса вне области поддержки и 3 неясных запроса; 7 высказываний содержат смешение языков. Жюри использует другой, скрытый набор того же типа.

```bash
python evaluate.py predictions.json dev_utterances.json
```

Формат `predictions.json`: `{"U001": ["SC01"], "U085": ["SC27", "SC04"], ...}`. Скрипт выводит точность определения основного сценария, долю полных совпадений и полноту распознавания нескольких намерений — с разбивкой по языку и типу запроса.

## Референсная архитектура

```text
 микрофон ──► STT (потоковый) ──► Уровень 1: Триаж ──► Уровень 2: LLM-маршрутизатор ──► Политика принятия решений ──► Исполнитель сценария ──► Ответ ──► TTS ──► динамик

                                              │                              │                                  │                           │             │

                                              └──────────────── Состояние диалога (язык, клиент, активный сценарий, стек, слоты) ────────────────┘

                                                                                         │

                                                                                   Панель трассировки
```

**Уровень 1 — Триаж** (быстро, для каждого высказывания)

- Язык: `ru`, `kk` или `mixed`; отвечайте на преобладающем языке клиента и переключайтесь, когда клиент меняет язык.
- Нормализация: числа, номера телефонов, госномера и даты.
- Сигналы срочности: ДТП произошло только что; клиент заболел за границей; мошенничество.
- Разделение высказывания с несколькими намерениями на отдельные части.

**Уровень 2 — LLM-маршрутизатор**

- Входные данные: высказывание или его часть, состояние диалога, каталог сценариев (`description`, `not_this_if`, несколько примеров).
- Формат выходных данных:

```json
{
  "scenarios": [
    {"scenario_id": "SC30", "confidence": 0.86, "reason": "money charged, policy not issued"},
    {"scenario_id": "SC29", "confidence": 0.78, "reason": "moved, wants to change address"}
  ],
  "alternatives": [{"scenario_id": "SC26", "confidence": 0.31}],
  "language": "ru",
  "slots": {"payment_date": "2026-09-30"},
  "is_continuation": false
}
```

**Политика принятия решений**

- `confidence ≥ 0.75` → запустить сценарий.
- `0.45–0.75` → `SYS_UNCLEAR`: задать один короткий вопрос с двумя наиболее вероятными вариантами.
- `< 0.45` два раза подряд или по просьбе клиента → перевести на оператора вместе с контекстом.
- Несколько сценариев → сначала `urgent`, затем остальные в порядке упоминания; подтвердить, что остальные вопросы также будут обработаны.
- Продолжение активного сценария → заполнить слоты, не запускать маршрутизацию повторно.

**Исполнитель сценария** — конечный автомат для каждого сценария: при необходимости идентифицировать клиента → по одному запросить недостающие слоты → вызвать действия → перед необратимыми действиями озвучить данные и получить подтверждение → завершить сценарий. При смене темы поместить текущий сценарий в стек и предложить вернуться к нему после завершения нового.

**Ответ** — генерация LLM, ограниченная сценарием, слотами, результатами действий и базой знаний. Не сообщайте факты, которых нет в данных.

**Быстрый путь (необязательно)** — сценарии с `fast_path_eligible` можно обслуживать без полного вызова LLM. Измерьте выигрыш во времени отклика.

## Правила общения

- 1–2 коротких предложения на реплику. Только один вопрос за раз.
- Сначала выразите понимание, затем действуйте: «Сочувствую. Давайте оформим обращение».
- В страховых случаях и жалобах проявляйте эмпатию; в срочных ситуациях действуйте спокойно и быстро.
- Произносите числа словами: «тридцать восемь тысяч тенге», а не «38000 KZT».
- При повторном озвучивании маскируйте персональные данные: `r***@mail.example`.
- Перед необратимыми действиями озвучьте данные и получите явное подтверждение «да».
- На вопрос «Вы робот?» отвечайте честно.
- При переводе на оператора передавайте краткое резюме контекста, чтобы клиенту не пришлось повторять информацию.

## Оценивание

- Жюри в реальном времени зачитывает 10 скрытых высказываний: простые запросы, смена темы, пограничные случаи, смешанная речь, казахский язык и запросы, которые не должны направляться в бизнес-сценарий.
- Каждое высказывание оценивается максимум в 3 балла: правильный основной сценарий; все сценарии для запроса с несколькими намерениями (в остальных случаях — правильный язык ответа); качество ответа с учётом данных.
- Задержка — необязательный показатель, который даёт только бонусные баллы: медленное решение не штрафуется. Измеряется время от окончания речи клиента до начала воспроизведения ответа (`latency_ms.total`), используется медиана по всему набору: ≤ 1,5 с → +2 балла, ≤ 3 с → +1 балл, > 3 с → 0 баллов. Жюри выборочно проверяет задержку секундомером.
- Персоны в скрытом наборе используют клиентов из `mock_backend.json`. Агент должен идентифицировать их по номеру телефона и использовать их данные.

## Разрешённые инструменты

Разрешены любые внешние или облачные API для LLM, STT и TTS. Классификаторы намерений — модели на основе энкодеров, обученные сопоставлять высказывания с намерениями, — нельзя использовать для выбора сценария.
